# ADR 0001: Rust runtime, pixi toolchain, monorepo layout

- Status: accepted
- Date: 2026-11-15

## Context

Broadcast ships a Tauri launcher that bundles a 217.8 MB universal Node binary plus
`server/`, `shared/`, `node_modules/{smol-toml,ws}` and supervises that Node child by
PID. Runtime logic is split across JavaScript (server, injector, CLI, cloud worker) and
Rust (launcher). Toolchains are installed ad hoc (rustup + nvm/npm).

## Decision

1. **All runtime code is Rust.** Local server, Codex CDP injector, agent runners, CLI and
   the cloud worker move to Rust crates. Node becomes a build-time tool only (Vite, web
   tests, e2e). The web app stays a static React + Vite SPA served by the Rust server;
   there is no Node SSR/BFF.
2. **pixi owns every toolchain.** `pixi.toml` pins `rust` (conda-forge, ships cargo +
   rustc), `nodejs` and `pnpm`. `rust-toolchain.toml` and rustup are removed. Extra
   targets come from `rust-std-<target>` packages in pixi features.
3. **The server runs in-process inside the desktop app.** The Tauri launcher links
   `broadcast-server` and starts it on a tokio task. No bundled Node, no child PID
   supervision.
4. **One local schema.** `db/migrations/0001_initial.sql` is applied with
   `rusqlite_migration`. It is the final schema of the Node server written with
   `IF NOT EXISTS`, so up-to-date existing databases open unchanged. Older Node-era
   databases are not migrated (no compat layer). D1 keeps its own chain in
   `apps/cloud/migrations`: wrangler records applied files by name in the deployed
   database, so collapsing the chain would mean rewriting production state.
5. **API parity is the acceptance bar.** Rust validation runs over `serde_json::Value`
   and reproduces the Node `ApiError` status, code and message exactly. The existing
   `test/server.test.mjs` suite runs against the Rust binary when
   `BROADCAST_SERVER_BIN` is set.

## Target layout

```
apps/
  desktop/        Tauri launcher (from src-tauri/), embeds broadcast-server
  web/            React + Vite SPA (from web/)
  cloud/          workers-rs worker, D1 migrations
crates/
  domain/         constants, input parsing/validation, row → record mapping
  config/         data directory, env, ports
  store/          rusqlite store + migrations
  server/         axum HTTP/SSE/WebSocket API, static web serving
  agents/         agent runners (Claude)
  codex/          Codex executable discovery, CDP injector (inject script via include_str!)
  cli/            `broadcast` CLI (clap), includes `broadcast runner <agent>`
packages/
  api-types/      TypeScript types generated by ts-rs
db/migrations/    local SQLite schema
docs/adr/
pixi.toml  Cargo.toml  pnpm-workspace.yaml  biome.json
```

## Migration order

Build crates next to the working JavaScript, verify parity, then cut over. Directory
moves, npm → pnpm, deleting Node packaging and the CI rewrite happen once, at cutover,
so packaging infrastructure is edited only once.

- [ ] Release check — universal DMG build, signing and notarization with pixi Rust

## Consequences

- One language for runtime behavior; the desktop bundle drops the Node binary.
- Validation parity is tedious but mechanical; the Node test suite was the oracle while
  both servers ran, and now drives the Rust binaries over HTTP and the CLI.
- Contributors need only pixi: `pixi install && pixi run dev`.
